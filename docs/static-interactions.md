# 静态阅读交互与服务端依赖

2026-10-22 排查发现，旧导出器会删除几乎所有脚本、禁用全部按钮、取消搜索表单并把未导出的链接换成文字。这会误伤并不需要服务端的功能。现已删除这种统一禁用逻辑，保留原项目的交互组件和结构化数据脚本。

## 浏览器中可完成

- 精选日期折叠、展开、只看未读、列表与详情收藏、收藏备份导入导出、字体和外观设置。
- 筛选菜单、同事件的其他报道、热点参与者名单、热点计算说明、事件内容导航、报道筛选与排序、热度图的浏览器操作。
- 详情菜单、复制链接和代码、查看大图、正文目录、回到顶部、更多菜单中的分享海报、Markdown 保存。
- 更新日志分类筛选、Agent 配置示例的客户端切换与复制、报告目录、原生报告日历和返回导航。
- 本次发布内容的标题、摘要和标签检索。结果明确标为“当前静态快照”，不冒充实时全文搜索。
- RSS、公开说明文件与站点 manifest 在发布时导出，阅读不依赖在线 API。

## 实现与兼容上游

`modules/shendeng/static-pages.ts` 在构建专用浏览器包时，用语法树仅剥离原路由的 loader、headers、meta 和服务端 HTTP 导入，保留原页面组件与事件处理器，不修改上游页面源码。路由数据只从原公共 HTTP 读取层获取，并写入页面快照；时间线完整翻页直到结束，同事件报道与事件后续也导出真正的公开快照。浏览器请求只将已登记的只读地址映射到导出文件，不伪造写入成功或运行模型。

原页面在只使用内存状态的路由上下文中运行；页面跳转映射到实际静态 HTML 地址。正文图片、卡片、Markdown 和资源沿用静态导出路径，不把本机回源地址交给读者。共享索引按发布版本取新数据，报道快照按内容生成文件名，避免沿用过期内容。详情返回保留同站来路返回和直接访问的父级入口。

原有自定义详情收藏/菜单与图片弹窗绑定已经移除，详情现在直接复用原组件；收藏列表仍复用原 local-state 的键和格式，并以本次导出清单说明可用页面，不把快照缺失错误地称为已撤稿。

## 确实需要公网服务端

| 操作 | 缺少的服务 |
| --- | --- |
| 在线反馈、截图上传 | 公网 API、校验、持久存储与上传处理 |
| 后台登录和管理 | 公网 API、数据库、安全会话与权限控制 |
| 原引擎实时全文检索 | 公网搜索 API 及持续更新的数据/索引 |
| REST API、MCP 工具实时查询 | 公网 API 服务与数据库 |
| 跨设备同步收藏 | 账号和同步服务；原项目本身是浏览器本机收藏 |

GitHub Pages 只能提供静态文件。本机常驻 API 当前监听 127.0.0.1，只用于采编和导出，不能直接由公网读者连接。未部署的在线操作保留可点击的说明，明确提示缺少公网服务端，不静默禁用、不假装提交成功，也不把本机密钥、Cookie 或数据库上传到 GitHub。

升级时检查路由导出形式、公共数据形状、同事件报道接口、图片和品牌路径、静态导航映射，运行原类型/后端/网页/冒烟检查以及 static-export.standalone.test.ts。新增依赖 API 的组件需要登记真实快照或明确配置公网服务；不能恢复“一律禁用按钮”的处理。
